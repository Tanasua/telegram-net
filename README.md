# telegram-net

Мережа телеграм-каналів місцевих новин Житомирської області: по одному каналу на
кожен (колишній) райцентр. Щогодини бот читає джерела (телеграм-канали, сайти),
відсіює рекламу й нерелевантне, генерує пост через OpenAI (з варіативним стилем —
короткі/довгі, з заголовком/без) і публікує з оригінальними фото/відео (галерея,
якщо кілька медіа).

## Архітектура

```
Scheduler (GitHub Actions, cron щогодини)
  → Fetchers: Telegram-джерела (Telethon) | Сайти з RSS | Сайти без RSS (скрапінг за CSS-селектором з конфігу)
  → Дедуп контенту (content hash)
  → Classifier (OpenAI): реклама? релевантність регіону? інтерес як новина?
  → [відхилено → лог] / [пройшло →]
  → Generator (OpenAI): варіативний пост (стиль обирається кодом, не моделлю)
  → Media planner: 1 фото / галерея (до 10 елементів на sendMediaGroup) / відео
  → Publisher (Telegram Bot API) → один з каналів
```

Конфіг (список джерел, канали, пороги релевантності) — у Google Sheets, один лист
на канал + лист `Channels`. Стан обробки (курсори читання, дедуп, лог публікацій)
— окремо, у SQLite/Postgres (`DATABASE_URL`). Це свідомий розподіл: Sheets легко
редагувати руками, але непридатний для щогодинного стану під навантаженням.

## Модулі (`src/telegram_net/`)

| Модуль | Що робить |
|---|---|
| `config.py` | `GoogleSheetsConfigSource` (робоче джерело) / `LocalJSONConfigSource` (той самий формат локально) |
| `db.py` | SQLAlchemy-моделі стану (джерела/курсори, сирі новини, медіа, класифікації, пости, лог публікацій) |
| `dedup.py` | Хеш нормалізованого тексту — та ж новина з кількох джерел не публікується двічі |
| `style.py` | Керований кодом розподіл стилів посту (довжина + заголовок/без) |
| `fetchers/telegram_fetcher.py` | Читання чужих публічних каналів через Telethon (MTProto), включно зі збиранням альбомів у галереї |
| `fetchers/web_fetcher.py` | RSS/Atom: автовиявлення через `<link>`, інакше пробує типові шляхи фіда (`/feed/` тощо); без RSS — джерело мовчить (без фолбека на OG-теги, див. нижче) |
| `fetchers/scrape_fetcher.py` | Для `type: "web_scrape"` (сайт зовсім без RSS) — список новин за CSS-селектором з конфігу джерела (`scrape_item_selector`/`scrape_title_selector`), без бекфілу на першому підключенні |
| `classifier.py` | OpenAI: реклама / релевантність / інтерес як новина (structured output) |
| `generator.py` | OpenAI: сам текст посту за обраним стилем |
| `media.py` | Розбивка медіа на пачки ≤10 (ліміт `sendMediaGroup`) |
| `publisher.py` | Публікація в Telegram Bot API (`sendMessage`/`sendPhoto`/`sendVideo`/`sendMediaGroup`) |
| `pipeline.py` | Оркестрація одного прогону |
| `scheduler.py` | Точка входу, яку викликає `.github/workflows/scheduler.yml` |

## Встановлення (локально — лише для розробки/тестів, продакшн — розділ нижче)

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
cp .env.example .env   # і заповнити — тільки для локального запуску/тестів
```

Продакшн-бот **не використовує `.env`** — він живе на GitHub Actions і бере ті
самі значення з GitHub Secrets (розділ "Запуск" нижче). `.env` потрібен лише
якщо хочеш прогнати конвеєр зі свого комп'ютера для перевірки.

### Ті самі значення (локально — у `.env`, у продакшні — GitHub Secrets)

- `TELEGRAM_BOT_TOKEN` — бот, доданий адміном у всі канали мережі.
- `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` — з https://my.telegram.org, для читання чужих публічних каналів-джерел через Telethon.
- `OPENAI_API_KEY`, `OPENAI_CLASSIFIER_MODEL`, `OPENAI_GENERATOR_MODEL` — назви моделей звір на platform.openai.com/docs/models. У коді навмисно немає дефолту: на момент написання (серпень 2026) сторонні джерела давали суперечливі дані про поточну лінійку моделей OpenAI, тож вгадувати ID тут — гарантований спосіб зламати запуск через кілька місяців.
- `GOOGLE_SHEETS_SPREADSHEET_ID` + `GOOGLE_SHEETS_CREDENTIALS_JSON` — якщо не задано, конвеєр читає конфіг локально з `data/sources_seed.json` (і попереджає про це в логах).

## Стартові дані (`data/sources_seed.json` + `data/sources_archive.json`)

Дослідження охопило всі 23 колишні райцентри Житомирської області, але **в роботі
зараз лише 7** — ті, для яких реально створено канали: Житомир, Бердичів,
Коростень, Звягель, Малин, Радомишль, Коростишів. Саме вони — в
`data/sources_seed.json`, і саме цей файл конвеєр читає за замовчуванням
(`LOCAL_CONFIG_PATH`), коли Google Sheets не підключено.

Решта 16 райцентрів (Овруч, Олевськ, Чуднів, Андрушівка, Ружин, Любар,
Попільня, Баранівка, Ємільчине, Народичі, Пулини, Романів, Брусилів, Лугини,
Хорошів, Черняхів) — **не видалені, а відкладені** в `data/sources_archive.json`,
той самий формат. Конвеєр цей файл не завантажує; коли дійде черга розширювати
мережу — просто перенеси потрібні об'єкти з `channels`/`sources` архіву назад
у робочий сід (чи вкажи `LOCAL_CONFIG_PATH=data/sources_archive.json`, щоб
попрацювати з ним окремо).

В обох файлах — той самий формат, що очікує `GoogleSheetsConfigSource`. Джерела
з позначкою `active: false` — ті, що дослідження позначило як "потребує ручної
перевірки" (наприклад, кілька конкуруючих груп з однаковою назвою, чи сайт, що
блокував автоматичний фетч) — звір і активуй вручну.

`telegram_chat_id` у кожного каналу (в обох файлах) — `null`: канали тобі
належить створити самому і додати туди бота адміном, я не можу вигадати їхні id.

Facebook-групи ("Підслухано ...") і Viber — свідомо не включені в сід
автоматизації: Facebook Graph API офіційно читає лише Pages (не групи) і
вимагає App Review, а Viber Public Account — окреме API, яке в цьому релізі
не реалізоване. Повний довідник (включно з FB/Viber, для ручного використання)
надсилався окремим xlsx-файлом під час дослідження джерел.

### Налаштування на канал (опціональні поля в `channels`, є дефолти)

| Поле | Дефолт | Що робить |
|---|---|---|
| `min_relevance` | `0.5` | поріг релевантності регіону — нижче не публікується |
| `max_posts_per_run` | `1` | скільки постів максимум публікувати на канал за один прогін (запобігає ситуації "один активний канал забрав увесь час, решта — нуль") |
| `max_age_minutes` | `60` | новина старша за це — не публікується взагалі, навіть якщо пройшла дедуп і релевантність |
| `length_weights` / `headline_probability` | 40/35/25%, 40% | керує варіативністю стилю постів (style.py) |
| `subscribe_cta` | `"Підписуйся на {name}"` | приписка в кінці посту, додається кодом після генерації (не LLM) |

## Стиль постів

Формат генератора (`generator.py`) змодельовано на реальному прикладі —
телеграм-канал Главреда (glavred.info, 37K+ підписників): один емодзі-маркер
настрою на самому початку, заголовок як перше речення (без окремого рядка),
пряма цитата з атрибуцією коли вона є в джерелі (і ніколи не вигадана, коли
її нема), довжина природно варіюється за інформаційним приводом. Заклик
підписатись — фіксована приписка, не частина того, що пише LLM.

## Запуск — все на GitHub Actions, без окремого сервера

Бот працює як щогодинний `.github/workflows/scheduler.yml` (`cron: "0 * * * *"` +
кнопка "Run workflow" для ручного запуску). Ніякого власного комп'ютера/VPS не
потрібно — GitHub сам піднімає чисту віртуалку щогодини, ставить залежності й
запускає `python -m telegram_net.scheduler`.

Це рішення закриває два бар'єри, які інакше зробили б GitHub Actions
непридатним для цього бота:

1. **Стан бота (SQLite) переживає між запусками.** Кожен прогін пише
   `state/telegram_net.db` і сам комітить його назад у репозиторій в кінці
   workflow — тому курсори читання й дедуп не губляться, хоч кожен запуск і
   стартує з чистої віртуалки. Це попутно й вирішує проблему "workflow
   вимикається після 60 днів без активності репозиторію" — коміт щогодини
   й є тією активністю.
2. **Логін у Telegram (Telethon) не можна зробити всередині CI** — потрібен
   код підтвердження з телефону, а CI не інтерактивний. Тому логін робиться
   **один раз** на будь-якому своєму комп'ютері через `scripts/create_telethon_session.py`,
   а результат (закодований у base64) зберігається як GitHub Secret і
   розкодовується назад у файл на початку кожного запуску workflow.

### Секрети (Settings → Secrets and variables → Actions → New secret)

| Назва | Що туди |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота від @BotFather |
| `TELEGRAM_API_ID` | з my.telegram.org |
| `TELEGRAM_API_HASH` | з my.telegram.org |
| `TELEGRAM_SESSION_B64` | вивід `scripts/create_telethon_session.py` (одноразово, локально) |
| `OPENAI_API_KEY` | ключ з platform.openai.com |
| `OPENAI_CLASSIFIER_MODEL` | напр. `gpt-5.6-luna` |
| `OPENAI_GENERATOR_MODEL` | напр. `gpt-5.6-terra` |

Google Sheets-секрети (`GOOGLE_SHEETS_*`) — не потрібні, поки конфіг береться
з `data/sources_seed.json` у самому репозиторії.

### Одноразовий локальний крок — сесія Telethon

На будь-якому своєму комп'ютері (потрібен лише раз, потім забудь про нього):

```bash
pip install telethon
TELEGRAM_API_ID=... TELEGRAM_API_HASH=... python scripts/create_telethon_session.py
```

Скрипт попросить номер телефону й код підтвердження з Telegram, а в кінці
виведе рядок — його встав у секрет `TELEGRAM_SESSION_B64`.

### Перевірка вручну

Actions → Hourly news pipeline → Run workflow — запускає прогін одразу, не
чекаючи наступної години. Дивись логи там же.

## Тести

```bash
.venv/bin/pytest
```

Усі тести — без мережі й без реальних credentials (мокнуті OpenAI-клієнт,
httpx через `respx`, Telethon-клієнт через легкий фейк).

## Свідомо не зроблено в цьому релізі (наступні кроки)

- **Facebook Pages / Groups, Viber** — архітектурно передбачено (`SourceType`
  включає `facebook_page`), фетчер не реалізований.
- **Кілька конкретних сайтів усе ще без новин** (не через лінь, а тому що не
  знайшлось чесного способу): `radmr.gov.ua` і `korostyshiv.misto.online` —
  на головній сторінці немає ні RSS, ні картки новини, яку можна було б надійно
  витягти за CSS-селектором (перший, схоже, тримає новини на іншій сторінці;
  другий виглядає радше як спільнотний застосунок голосувань, а не новинний
  сайт). `04141.com.ua` — за Cloudflare, звичайний запит блокується незалежно
  від User-Agent. `zhitomir.info` — стабільно віддає 429 (рейт-ліміт), а не
  блокування за заголовками, тож частіші спроби лише погіршать ситуацію.
- **Postgres у продакшн-режимі** — код через `DATABASE_URL` вже сумісний, міняти
  тільки рядок підключення; Alembic-міграції не додавав, поки схема не
  стабілізувалась на реальному використанні.
- **Стиснення відео** понад 50 МБ (ліміт стандартного Bot API) — для типових
  коротких новинних відео це рідкість; якщо стане проблемою, рішення — локальний
  Bot API сервер (до ~2 ГБ).
