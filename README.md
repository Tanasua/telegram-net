# telegram-net

Мережа телеграм-каналів місцевих новин Житомирської області: по одному каналу на
кожен (колишній) райцентр. Щогодини бот читає джерела (телеграм-канали, сайти),
відсіює рекламу й нерелевантне, генерує пост через OpenAI (з варіативним стилем —
короткі/довгі, з заголовком/без) і публікує з оригінальними фото/відео (галерея,
якщо кілька медіа).

## Архітектура

```
Scheduler (зовнішній cron/systemd timer, щогодини)
  → Fetchers: Telegram-джерела (Telethon) | Сайти (RSS/OG-теги)
  → Дедуп контенту (content hash)
  → Classifier (OpenAI): реклама? релевантність регіону? інтерес як новина?
  → [відхилено → лог] / [пройшло →]
  → Generator (OpenAI): варіативний пост (стиль обирається кодом, не моделлю)
  → Media planner: 1 фото / галерея (до 10 елементів на sendMediaGroup) / відео
  → Publisher (Telegram Bot API) → один з каналів
```

Конфіг (список джерел, канали, пороги релевантності) — у Google Sheets, один лист
на канал + лист `Channels`. Стан обробки (курсори читання, дедуп, лог публікацій)
— окремо, у SQLite/Postgres (`DATABASE_URL`). Це свідомий розподіл: Sheets легко
редагувати руками, але непридатний для щогодинного стану під навантаженням.

## Модулі (`src/telegram_net/`)

| Модуль | Що робить |
|---|---|
| `config.py` | `GoogleSheetsConfigSource` (робоче джерело) / `LocalJSONConfigSource` (той самий формат локально) |
| `db.py` | SQLAlchemy-моделі стану (джерела/курсори, сирі новини, медіа, класифікації, пости, лог публікацій) |
| `dedup.py` | Хеш нормалізованого тексту — та ж новина з кількох джерел не публікується двічі |
| `style.py` | Керований кодом розподіл стилів посту (довжина + заголовок/без) |
| `fetchers/telegram_fetcher.py` | Читання чужих публічних каналів через Telethon (MTProto), включно зі збиранням альбомів у галереї |
| `fetchers/web_fetcher.py` | RSS/Atom з автовиявленням, інакше — знімок за OG-тегами |
| `classifier.py` | OpenAI: реклама / релевантність / інтерес як новина (structured output) |
| `generator.py` | OpenAI: сам текст посту за обраним стилем |
| `media.py` | Розбивка медіа на пачки ≤10 (ліміт `sendMediaGroup`) |
| `publisher.py` | Публікація в Telegram Bot API (`sendMessage`/`sendPhoto`/`sendVideo`/`sendMediaGroup`) |
| `pipeline.py` | Оркестрація одного прогону |
| `scheduler.py` | Точка входу для cron/systemd timer |

## Встановлення

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
cp .env.example .env   # і заповнити
```

### Обов'язково заповнити самостійно (нічого з цього не вигадано за тебе)

- `TELEGRAM_BOT_TOKEN` — бот, доданий адміном у всі канали мережі.
- `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` — з https://my.telegram.org, для читання чужих публічних каналів-джерел через Telethon.
- `OPENAI_API_KEY`, `OPENAI_CLASSIFIER_MODEL`, `OPENAI_GENERATOR_MODEL` — назви моделей звір на platform.openai.com/docs/models. У коді навмисно немає дефолту: на момент написання (серпень 2026) сторонні джерела давали суперечливі дані про поточну лінійку моделей OpenAI, тож вгадувати ID тут — гарантований спосіб зламати запуск через кілька місяців.
- `GOOGLE_SHEETS_SPREADSHEET_ID` + `GOOGLE_SHEETS_CREDENTIALS_JSON` — якщо не задано, конвеєр читає конфіг локально з `data/sources_seed.json` (і попереджає про це в логах).

## Стартові дані (`data/sources_seed.json` + `data/sources_archive.json`)

Дослідження охопило всі 23 колишні райцентри Житомирської області, але **в роботі
зараз лише 7** — ті, для яких реально створено канали: Житомир, Бердичів,
Коростень, Звягель, Малин, Радомишль, Коростишів. Саме вони — в
`data/sources_seed.json`, і саме цей файл конвеєр читає за замовчуванням
(`LOCAL_CONFIG_PATH`), коли Google Sheets не підключено.

Решта 16 райцентрів (Овруч, Олевськ, Чуднів, Андрушівка, Ружин, Любар,
Попільня, Баранівка, Ємільчине, Народичі, Пулини, Романів, Брусилів, Лугини,
Хорошів, Черняхів) — **не видалені, а відкладені** в `data/sources_archive.json`,
той самий формат. Конвеєр цей файл не завантажує; коли дійде черга розширювати
мережу — просто перенеси потрібні об'єкти з `channels`/`sources` архіву назад
у робочий сід (чи вкажи `LOCAL_CONFIG_PATH=data/sources_archive.json`, щоб
попрацювати з ним окремо).

В обох файлах — той самий формат, що очікує `GoogleSheetsConfigSource`. Джерела
з позначкою `active: false` — ті, що дослідження позначило як "потребує ручної
перевірки" (наприклад, кілька конкуруючих груп з однаковою назвою, чи сайт, що
блокував автоматичний фетч) — звір і активуй вручну.

`telegram_chat_id` у кожного каналу (в обох файлах) — `null`: канали тобі
належить створити самому і додати туди бота адміном, я не можу вигадати їхні id.

Facebook-групи ("Підслухано ...") і Viber — свідомо не включені в сід
автоматизації: Facebook Graph API офіційно читає лише Pages (не групи) і
вимагає App Review, а Viber Public Account — окреме API, яке в цьому релізі
не реалізоване. Повний довідник (включно з FB/Viber, для ручного використання)
надсилався окремим xlsx-файлом під час дослідження джерел.

## Запуск

```bash
.venv/bin/python -m telegram_net.scheduler
```

Розклад — зовнішній (cron/systemd timer), напр. щогодини:

```
0 * * * * cd /path/to/telegram-net && .venv/bin/python -m telegram_net.scheduler
```

## Тести

```bash
.venv/bin/pytest
```

Усі тести — без мережі й без реальних credentials (мокнуті OpenAI-клієнт,
httpx через `respx`, Telethon-клієнт через легкий фейк).

## Свідомо не зроблено в цьому релізі (наступні кроки)

- **Facebook Pages / Groups, Viber** — архітектурно передбачено (`SourceType`
  включає `facebook_page`), фетчер не реалізований.
- **Per-site скрапери** для сайтів без RSS і без OG-тегів — зараз такі сайти
  просто не дають нових новин, а не ламають конвеєр.
- **Postgres у продакшн-режимі** — код через `DATABASE_URL` вже сумісний, міняти
  тільки рядок підключення; Alembic-міграції не додавав, поки схема не
  стабілізувалась на реальному використанні.
- **Стиснення відео** понад 50 МБ (ліміт стандартного Bot API) — для типових
  коротких новинних відео це рідкість; якщо стане проблемою, рішення — локальний
  Bot API сервер (до ~2 ГБ).
